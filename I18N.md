# Tradução (PT / EN)

O site troca de idioma pelo toggle **EN | PT** no header, sem reload e sem mudar
a URL. A escolha fica salva no navegador (`localStorage`).

## Como funciona

Todo texto vive em dois dicionários: [`messages/en.json`](messages/en.json) e
[`messages/pt.json`](messages/pt.json). Os componentes leem esses arquivos por
uma chave, nunca texto direto no código.

```tsx
const t = useTranslations()
<h2>{t.caseCommon.initiatives}</h2>   // "Initiatives" ou "Iniciativas"
```

**Os dois arquivos precisam ter exatamente as mesmas chaves.** Isso é garantido
pelo TypeScript: se faltar uma chave no `pt.json`, `npx tsc --noEmit` acusa erro.
A única exceção intencional é a seção `projects` (explicada abaixo).

## Os dois tipos de conteúdo

O trabalho restante se divide em dois tipos **independentes** — podem ser feitos
em qualquer ordem, não há dependência entre eles.

### Tipo 1 — Texto escrito direto no JSX

Títulos de seção e parágrafos hardcoded nas páginas de case.

**Exemplos prontos:**
[`app/work/rapid-churn-retention-intervention/page.tsx`](app/work/rapid-churn-retention-intervention/page.tsx)
e [`app/work/engineering-enablement/page.tsx`](app/work/engineering-enablement/page.tsx)

**Como fazer:**

1. Adicione as chaves em `en.json` e `pt.json` dentro de `cases.<nomeDoCase>`:

```json
"cases": {
  "meuCase": {
    "challengeTitle": "The challenge",
    "challengeText": "Texto longo aqui..."
  }
}
```

2. No componente, importe e use:

```tsx
import { useTranslations } from '@/lib/i18n/provider'

export default function MinhaCasePage() {
  const t = useTranslations()
  return <h2>{t.cases.meuCase.challengeTitle}</h2>
}
```

3. Textos que se repetem em vários cases ("Initiatives", "Explore other cases",
   "← Back") já existem em `caseCommon` — reutilize em vez de duplicar.

### Tipo 2 — Dados vindos de `portfolio-data.ts`

Nome do projeto, headline, resumo, tags, iniciativas.

**Exemplo pronto:** `auden-college`

Aqui há uma separação importante: **estrutura não se traduz, texto sim.**

| Fica em `portfolio-data.ts` | Vai para os dicionários |
|---|---|
| `slug` (traduzir quebraria a URL) | `name`, `headline`, `summary` |
| `cover` (caminho de imagem) | `domain`, `role`, `period`, `team` |
| `year`, `featured`, `hidden` | `tags`, `whatIDid`, `about` |
| `metric.value` (número) | `metric.label`, `initiatives`, `outcome` |

**Como fazer:**

1. Em `pt.json`, adicione o projeto dentro de `projects`, chaveado pelo **slug**:

```json
"projects": {
  "meu-projeto": {
    "name": "Nome em português",
    "headline": "Headline traduzida",
    "summary": "Resumo traduzido",
    "tags": ["Tag1", "Tag2"],
    "whatIDid": ["item 1", "item 2"],
    "about": ["parágrafo 1", "parágrafo 2"],
    "initiatives": [
      {
        "title": "...",
        "challenge": "...",
        "focusLabel": "Foco estratégico",
        "focus": "...",
        "solution": "..."
      }
    ],
    "outcome": ["..."]
  }
}
```

Só os campos que você quiser traduzir — o que faltar cai automaticamente para o
inglês do `portfolio-data.ts`.

2. Na página do case, troque a busca manual pelo hook:

```tsx
// antes
const project = projects.find((p) => p.slug === 'meu-projeto')

// depois
import { useProject } from '@/lib/i18n/provider'
const project = useProject('meu-projeto')
```

O resto do componente não muda: `project.name`, `project.cover`, `project.tags`
continuam funcionando igual, já traduzidos.

3. Onde a página lista **outros** projetos (cards de "Explore other cases"),
   troque o import estático pelo hook:

```tsx
// antes
import { projects } from '@/lib/portfolio-data'

// depois
import { useProjects } from '@/lib/i18n/provider'
const projects = useProjects()
```

> **Importante:** `en.json` tem `"projects": {}` vazio de propósito. O inglês já
> está no `portfolio-data.ts` e é usado como está — só os outros idiomas
> sobrescrevem. Por isso essa seção é a única que não precisa de paridade.

## Convenções de tradução

- **Termos técnicos ficam em inglês**: design system, checkout, discovery,
  delivery, handoff, baseline, funnel, A/B test, trade-off, SaaS, e-commerce.
  É como se fala no mercado brasileiro de produto.
- **Não traduza** nomes próprios (Ditto, AUDEN, Qeevo, Framer, Figma, Clarity)
  nem referências legais (Decreto nº 12.456/2025, Portaria MEC nº 378/2025).
- **Não traduza** o `MarketingAgilityFlow`: o texto em português ali é uma
  simulação de tela real do produto, não conteúdo do portfólio.

## Verificar antes de commitar

```bash
npx tsc --noEmit    # acusa chave faltando no pt.json
npx next build      # confirma que tudo compila
```

## Adicionar um terceiro idioma

1. Crie `messages/es.json` com as mesmas chaves
2. Em [`lib/i18n/config.ts`](lib/i18n/config.ts), adicione `'es'` em `LOCALES` e
   o rótulo em `LOCALE_LABELS`
3. Em [`lib/i18n/provider.tsx`](lib/i18n/provider.tsx), importe e registre no
   objeto `dictionaries`

Nenhum componente precisa mudar.

## Arquivos

| Arquivo | Papel |
|---|---|
| `messages/en.json`, `messages/pt.json` | Os dicionários |
| `lib/i18n/config.ts` | Idiomas disponíveis e padrão |
| `lib/i18n/provider.tsx` | Contexto e hooks (`useTranslations`, `useProject`, `useProjects`) |
| `lib/i18n/projects.ts` | Mescla estrutura + tradução dos projetos |
| `components/language-toggle.tsx` | O switch EN / PT |
